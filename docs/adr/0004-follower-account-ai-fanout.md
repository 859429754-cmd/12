# ADR-0004: 主账户 AI 决策与跟随账户复制执行

## 状态

已接受。

本 ADR 仍然有效，但被 ADR-0005 补充：控制台安全使用账号登录/RBAC，不再使用 Trade PIN 或操作验证码。

## 背景

当前系统已经具备 ETH 1h 趋势策略、DeepSeek 五档风控、Gate.io 真实网关、订单生命周期、readiness、worker 心跳和云端 systemd 运行能力。用户需要新增第二个 Gate.io 账户，让第二个账户跟随主账户同一套策略和同一次 AI 决策执行，并拥有独立控制台视图。

## 决策

采用“单策略、单 AI 决策、多账户执行”的轻量架构：

```text
趋势策略信号
  -> DeepSeek 主/备 API 分析一次
  -> RiskManager 生成五档仓位
  -> 主账户 trend 执行
  -> 跟随账户 follower 按同一 decision_id 执行
```

### 主账户

- 账户槽位：`trend`
- 负责运行当前生产趋势策略。
- 负责触发 DeepSeek 分析。
- 负责生成系统唯一的 AI 决策和 RiskManager 仓位档。
- 负责主账户真实开仓、平仓、原生止损和订单生命周期审计。

### 跟随账户

- 账户槽位：`follower`
- 不重新计算策略。
- 不重新调用 DeepSeek。
- 不生成独立交易方向。
- 只接收主账户同一 `signal_id/decision_id` 的最终决策。
- 按自身余额、最大杠杆、跟随比例、最小下单量、持仓状态和 API 状态独立裁剪下单数量。
- 失败时不影响主账户，但必须落库审计并在控制台显示。

### 震荡账户

- 账户槽位：`range`
- 当前只是震荡策略预留账户。
- 不作为 follower 兼容槽位。
- 不执行趋势跟随，直到震荡策略正式实现并通过回测/实盘前验证。

## 风控约束

- AI 不允许发明方向，方向仍由本地趋势策略决定。
- 跟随账户不能绕过主账户 RiskManager 的阻断。
- 跟随账户不能绕过自身账户级安全检查。
- 跟随账户出现未知订单状态时，禁止盲目重复下单。
- 跟随账户下单前必须检查余额、持仓、挂单、最小下单量、API 可用性和账户级杠杆上限。
- 主账户执行失败时，跟随账户默认不执行新开仓。
- 主账户平仓信号允许跟随账户独立平仓，但必须以跟随账户真实持仓为准。
- 跟随账户原生止损必须基于跟随账户实际成交价和同一策略信号 ATR 重新计算，不能直接复制主账户止损价。

## DeepSeek 主备

- 主 Key：`DEEPSEEK_API_KEY`
- 备用 Key：`DEEPSEEK_BACKUP_API_KEY`
- 每次信号只应得到一个 AI 决策。
- 主 Key 超时、5xx、网络错误、JSON 无效或额度不可用时，才允许切换备用 Key。
- 不做双 Key 投票，不重复调用来追求更好答案。
- 日志、审计、API 响应不得输出任何 Key 明文。

## 控制台

第一阶段不是完整多租户 SaaS，而是一个后端服务提供三个账户视图：

- `admin`：可看全部账户，可配置跟随开关、API 和账户参数。
- `account1`：主账户视图。
- `account2`：跟随账户视图。
- `range`：震荡预留账户视图。

账户1和账户2展示同一份 AI 市场分析、新闻判断、订单流判断、密集区判断、形态判断和五档仓位结果；账户余额、实际下单数量、持仓、盈亏、订单状态和止损状态独立展示。

## 不做

- 不在第一阶段做完整租户计费、注册、权限矩阵和 SaaS 隔离。
- 不让账户2独立调用 AI。
- 不让账户2独立计算策略。
- 不让账户2接管主账户失败后的交易方向。
- 不把 `range` 当作 `follower` 的兼容来源。

## 验证

- mock 双账户开仓、平仓、反手和止损流程。
- 主账户通过、跟随账户失败时，主账户订单不回滚，跟随账户状态记录为 failed/unknown。
- 主账户阻断时，跟随账户不得开仓。
- DeepSeek 主 Key 失败时备用 Key 只调用一次并生成单一决策。
- 全量验证命令：
  - `python -m compileall ai_quant_trader tests scripts`
  - `python -m pytest -q`
  - `cd console && npm.cmd run build`
  - `python scripts/public_repo_preflight.py`
