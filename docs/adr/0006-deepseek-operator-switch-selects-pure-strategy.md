# ADR-0006: DeepSeek 运营开关选择纯策略模式

- 状态：Accepted
- 日期：2026-07-13

## 背景

旧语义把 `ai.enabled=false` 解释为 DeepSeek 不可用，并在 live 模式阻断新开仓。用户现在明确要求：主动关闭 DeepSeek 时，系统继续执行已经验证的 ETH 1h 本地趋势策略，而不是停止交易。

该决策只适用于管理员主动关闭。AI 增强模式下出现 API 鉴权失败、额度耗尽、超时、无效 JSON 等异常，仍按 AI 增强模式的 fail-closed/保守降级合同处理，不能偷偷退化为纯策略开仓。

## 决策

`ai.enabled` 选择两种明确的决策策略：

```text
true  -> ai_assisted
false -> pure_strategy
```

`pure_strategy`：

- 不调用 DeepSeek，包括小时交易、价格唤醒、重大新闻复评和优化提案。
- 入场数量以本地 KC+VOL+KDJ 策略的 `suggested_qty` 为基准。
- 不使用 AI 五档、新闻/订单流仓位裁剪、AI 漂移阻断或持仓复评加仓。
- 保留逐标的开仓授权、暂停开关、交易所对账、订单状态机、同向重复持仓保护、总杠杆上限、OHLCV/时钟新鲜度、Gate 原生 ATR 止损、软件止损和 KC 中轨退出。
- 重大新闻仍可采集和展示，但不参与纯策略入场仓位。

`ai_assisted`：

- 本地策略仍是方向来源。
- DeepSeek 与五档模型可以在硬风控内受控升档、维持、降档或阻断。
- DeepSeek 异常不得自动切换成纯策略实盘开仓。

真正停止所有新开仓必须使用 `opening_paused`/撤销标的授权，不能依赖 `ai.enabled`。

## 后果

- 管理员可以在控制台“快速控制”中切换 AI 增强和纯策略。
- 切换为纯策略可能增加此前会被 AI 阻断的交易数量；这不是风险降低开关。
- 纯策略模式不承诺比 AI 增强模式盈利更多，必须分别做交易账本和样本外效果审计。
- 云端从旧版本升级到本决策前，若 `ai.enabled=false` 且开仓未暂停，部署会改变真实交易行为；发布必须先暂停新开仓并在部署后人工重新授权。
