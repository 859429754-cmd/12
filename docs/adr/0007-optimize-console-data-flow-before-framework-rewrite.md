# ADR-0007: 先优化控制台数据流，不重写前端框架

- 状态：Accepted
- 日期：2026-07-13

## 背景

控制台加载慢的主要原因不是 React/Vite 包体，而是首页把 Gate 余额、持仓、readiness、订单、决策、新闻和 5000 根 K 线绑定到一次全量轮询。任何一个远端接口变慢都会拖住整页，并可能短暂把余额或持仓显示为零。

## 决策

保留 React + TypeScript + Vite + FastAPI + lightweight-charts，不在实盘系统上进行高风险框架重写。数据流改为：

- 账户余额和持仓异步刷新，不阻塞核心页面。
- Gate 短暂超时保留最后一次可信快照，显式标记缓存/过期，不用零值覆盖。
- 实时价格 10 秒刷新；核心状态 30 秒；新闻 30 秒；快速 K 线 60 秒。
- 5000 根完整 K 线只在首次进入或切换标的/周期/数据源时加载。
- AI 分档审计和安全事件等重查询最多 120 秒刷新一次。
- 登录账户切换时清空上一账户的余额、持仓、订单和 AI 审计状态，避免跨账户短暂串屏。

后续成熟终端升级采用 SSE/WebSocket 增量推送余额、持仓、订单、AI 决策和新闻；在此之前不替换交易内核或策略执行进程。

## 后果

- 首屏更快，Gate 网络抖动不再阻塞全部模块。
- 页面显示必须区分实时、缓存、过期和读取失败。
- 轮询仍不是最终形态；SSE/WebSocket 是后续独立阶段，需要断线重连、事件序列号和快照补偿测试。
