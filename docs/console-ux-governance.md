# AI 量化控制台 UI 与功能优化制度

本文档用于约束控制台后续迭代。目标不是“做得好看”，而是让实盘值班人员在 10 秒内判断：账户是否安全、策略是否允许开仓、AI 是否阻断、新闻是否异常、交易链路是否可用。

## 一、每版优化闭环

每次控制台优化必须按以下顺序执行：

1. 明确问题
   - 是否存在信息重复、状态不一致、操作入口不清晰、交易风险提示不足。
   - 是否有英文内部字段、错误码、调试文本泄漏到用户界面。
   - 是否有慢接口阻塞关键实盘状态展示。

2. 设计取舍
   - 首页只展示实盘值班必需信息：账户、持仓、盈亏、AI 档位、新闻、对账、订单链路。
   - 非首要信息进入折叠区、二级页面或审计页。
   - 危险操作必须带明确确认机制；验证码不是正式认证，只能作为临时二次确认。

3. 实现与自审
   - 不改策略逻辑、AI 决策逻辑、RiskManager、Gateway，除非任务明确要求。
   - 前端慢接口必须降级，不得拖垮账户、持仓、实盘模式等核心状态。
   - K线图必须显示数据源、周期、OHLC、成交量、指标、订单/AI标记和密集区。

4. 验证
   - `cd console && npm.cmd run build`
   - `python -m pytest tests/test_console_api.py -q`
   - 涉及后端时运行全量 `python -m pytest -q`
   - 公网或本地浏览器实际打开页面，检查首屏是否能读懂。

5. 复盘与询问
   - 输出本版改动、验证结果、残留问题。
   - 明确询问用户是否满意，若不满意进入下一版迭代。

## 二、首页验收标准

首页第一屏必须能直接看到：

- 账户权益、可用余额。
- 当前持仓方向、开仓价、标记价、止损价、浮动盈亏。
- ETH 五档仓位映射：block / weak / normal / strong / full。
- AI 当前动作：允许、降仓、阻断、等待。
- 交易所安全闸和最近对账状态。
- 最新新闻快讯，不显示内部错误码或调试标记。
- 最近订单状态，不显示原始英文状态。

首页不得重复展示同一组账户指标。重复信息只能出现在折叠审计区或二级页面。

## 三、K线图验收标准

专业图表页必须包含：

- 周期切换、数据源切换、展示区间切换。
- 当前或十字光标对应 K 线的 O/H/L/C、涨跌幅、成交量。
- KC 中轨/上下轨、成交量、订单标记、AI 决策标记、密集区价格线开关。
- 图表数据不足或接口异常时，必须显示明确降级提示，而不是空白图。

## 四、风险边界

- 控制台 UI 不能替代实盘风控；真实下单必须继续经过本地策略信号、DeepSeek 五档裁剪、RiskManager、Gateway。
- 公网只读暴露仍有信息泄漏风险。大资金无人值守前，必须恢复正式认证、审计登录和访问控制。
- “视觉更好看”不能优先于“状态更准确”。任何动画、装饰和重排都不能遮挡账户、持仓、AI、风控、订单链路。
